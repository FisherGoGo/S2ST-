# 知识库维护规范

## 单一职责和稳定引用

概念页解释机制，路线页比较连接方式，模型页追踪实现与自己的理解，论文卡保存版本与证据，实验页记录真实执行。不要把同一实验数值在多份笔记抄来抄去；用原卡/实验链接引用。

本次用 `Pxx` 标识模型研究论文，`Sxx` 综述/方法回顾，`Exx` 数据或评价证据；是本库内部 ID，不代表来源级别。后续递增且不复用，不因论文发表年份变化而更名。引用正式发表版时保留 arXiv 初版日期和所读版本。

所有关键事实注明原始 URL、核验日期及范围，精确结果增加页/表。作者承认的局限要定位；个人理解和假设明确标记。`updated` 在有实质变更时手动更新，不用自动时间替代阅读状态。

## Obsidian 与文件约定

仓库根是 `01 STS_NOTE`，链接使用 `/`，文件名避免 `: ? * # |` 等符号。普通正文相对 Markdown 链接；模板固定导航使用 `[[S2ST-Research/README|首页]]`。重命名尽量在 Obsidian 内完成，并检查反链与外部代码文档链接。

三个规范模板只保存在本目录的 `模板` 文件夹，其他目录的模板入口不保存重复正文。新模板字段尽量扁平，状态使用明确文本，不使用无法核验的“已完成”标签。

## Git 与大文件

当前目录属于上级 `D:\Project\Note\Science` Git 仓库，未在本次初始化、提交或改动上级配置。新增 ignore 仅作用于当前笔记/代码子树：忽略模型缓存、数据、运行输出、虚拟环境和动态工作区，不忽略可维护的 Markdown 与实验配置。

原始录音、模型和数据集置于代码侧私有 data/models 或仓库外。导出 PDF、截图和音频先判断体积及隐私；小型可分享图可入附件。不要忽略全部 JSON：配置、元数据示例和来源注册表仍需版本管理。

更新后运行代码侧 `scripts/check_kb.py --kb '完整知识库目录'` 检查链接。工具只核对本地目标与基本路径，不代表外部来源未失效，更不代表研究结论已核验。
